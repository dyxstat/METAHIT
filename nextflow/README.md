# METAHI-T native Nextflow DSL2 workflow

`main_dsl2.nf` is the METAHI-T workflow entry point. It is a native DSL2
implementation: each analysis stage is a named Nextflow process with declared
inputs, outputs, compute resources, Conda environment, container image, and
published result directory. It does **not** use the retired generic
`metahict_nextflow_driver.py` execution path.

The established METAHI-T module commands remain the scientific implementation
run inside their corresponding processes. This keeps their analytical behavior
while Nextflow owns the dependency graph, task isolation, restart support, and
execution provenance.

## Workflow graph

```text
SG reads ─┐
          ├─ PREPROCESSING ─ ASSEMBLY ─┬─ ALIGNMENT ─┬─ CONTACT
Hi-C reads┘                            │             └─ BINNING ─ REASSEMBLY ─ ANNOTATION ─ SCAFFOLDING
          └─ PREPROCESSING ────────────┘                              └─ MGE_ALIGNMENT ─ MGE_CONTACT ─ MGE
```

`PREPROCESSING` runs once for the shotgun pair and once for the Hi-C pair.
The MGE branch intentionally realigns the Hi-C reads to
`reassembly/combined_contigs.fa` and reconstructs a contact matrix from that
new BAM. It does not reuse the original-assembly alignment or contact matrix.
For module-only reruns where the reassembly-specific MGE contact matrices
already exist, provide `--reassembly_dir` and `--mge_contact_dir`; in that mode
the workflow runs only the final `MGE` process and skips `MGE_ALIGNMENT` and
`MGE_CONTACT`.

## Reusing existing module outputs

Selected-module runs can read previous-stage outputs either from the standard
Nextflow result layout or from explicit user-provided directories. Use explicit
directories when reusing results generated by an older script run or stored in
a custom location. Supported direct-directory parameters are:

- `--sg_preprocessing_dir`
- `--hic_preprocessing_dir`
- `--assembly_dir`
- `--alignment_dir`
- `--coverage_dir`
- `--binning_dir`
- `--reassembly_dir`
- `--mge_alignment_dir`
- `--mge_contact_dir`

`--contact_dir`, `--annotation_dir`, and `--scaffolding_dir` are not provided
because those standard module outputs are not currently consumed by downstream
Nextflow processes. The MGE-specific contact output is handled separately by
`--mge_contact_dir`. For multi-sample runs, direct paths may include
`{sample}`, which is replaced with the sample name.

## Run the bundled example

From the repository root:

```bash
nextflow/run_metahict_nextflow.sh run nextflow/main_dsl2.nf \
  -profile local \
  --samplesheet nextflow/assets/example_data_samplesheet.csv \
  --out_root /path/to/metahict_results \
  --report_dir /path/to/metahict_reports \
  -work-dir /path/to/metahict_work \
  -ansi-log false
```

The sample sheet must include `sample`, `sg1`, `sg2`, `hic1`, and `hic2`.
Paths may be absolute or relative to the METAHI-T repository. The optional
`*_extra_args` columns in the distributed example sample sheet are passed to
their matching module process.

Large databases (GTDB-Tk release 220, geNomad, and
CheckM/CheckM2) are external configuration/data requirements; they are not
embedded in the workflow or container image.

Their paths are regular workflow parameters shared by every profile:
`--checkm_db`, `--checkm2_db`, `--gtdbtk_db`, and `--genomad_db`.  The distributed defaults point to the corresponding directories
under `<project>/databases/`.  Override them for a custom database location;
do not export Docker or Apptainer environment variables.

## Execution profiles

- `local`: runs against the installed local METAHI-T environments.
- `conda`: verifies the complete, exact locked METAHICT environment bundle in
  `<project>/conda_envs/` before starting. Run
  `bash installation/run_setup_in_venv.sh` first; the profile requires
  `metahict_env`, `checkm2`, `gtdbtk-2.4.0`, and `genomad`.
- `docker`: uses the configured container image references.  Development can
  use locally built module images; a release run uses one tested all-tools
  image supplied with `--container_image_override`.
- `apptainer`: uses the configured SIF image or an all-tools release image
  converted/pulled by Apptainer.  A public release image is produced only
  after the full example-data tests have passed.

Build or refresh container images with:

```bash
nextflow/containers/build_containers.sh docker
nextflow/containers/build_containers.sh apptainer
```

## Test the workflow graph

The smoke test runs every process in DSL2 stub mode and verifies the expected
stage outputs, including the separate MGE re-alignment and MGE-contact stages:

```bash
bash nextflow/ci/run_smoke_ci.sh
```

Stub mode tests workflow contracts, staging, graph wiring, and publication. A
full biological run requires reads sufficient for binning plus the configured
reference databases.

`main_wrapper_legacy.nf` and `modules/local/metahict_step_legacy.nf` preserve
the former generic wrapper for comparison only. They are not invoked by
`main_dsl2.nf`.

`REPRODUCIBILITY.md` is the canonical human-readable record for the workflow
graph, process resources, exact dependency locks, databases, and defaults.
